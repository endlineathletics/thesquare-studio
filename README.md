COURT 4 = 옛 요가 대관 공간(배드민턴 · 피클볼 코트 크기가 같음) — 혼자 1시간 **75,000원**(나머지 52,800원 · `booking-config.js` `prices`, 가격이 다른 코트는 표 머리줄에 작게 금액). 금액 = 칸마다 그 코트 가격의 합 — 섞이면 요약 바 `COURT 1·4 · 10:00~12:00 (2시간) · 255,600원`, 신청 요약 · 문자 접수 내역 `52,800원 × 2 + 75,000원 × 2` (실제 결제 금액은 관리프로그램이 계산). 피클볼 페이지(`data-space="pickleball"`)는 같은 배드민턴센터의 COURT 4 한 열만 — `apiSpace: 'badminton'`(조회 · 신청 공간) · `courtIdx: [3]`(표의 열 → 관리프로그램 코트 index) · `sport: 'pickleball'`. 같은 칸이라 한쪽에서 잡히면 다른 쪽도 '—' (관리프로그램 slots 는 4코트가 다 오고 피클볼 화면은 court 3 만 씀). 신청(`book`)엔 `sport`('badminton' | 'pickleball' — 직원이 보고 네트를 바꿔 놓음, 피클볼은 court 3 만). booking.js 안의 코트는 늘 '표의 열' index 이고 관리프로그램과 주고받을 때만 `apiCourt` / `colOf` 로 바꿈. 코트가 하나뿐인 피클볼 화면도 요약 · 확인창에 'COURT 4' 를 보여 줌(`SHOW_C`). 결제 결과는 관리프로그램이 신청 종목으로 돌아갈 페이지를 고름(피클볼 = `pickleball.html?pay=…#rental`) — 결과가 다른 페이지로 와도 `bkPay` 는 같은 관리프로그램 공간이면 처리(칸 풀기 · 완료 화면 예약 내용). **배포는 관리프로그램(4코트 · 코트별 가격 · sport) 먼저** — 옛 관리프로그램은 court 3 을 모르는 칸(invalid_item)으로 거절함

  - 한 신청 = 이어진 시간 범위 하나 + 코트 1~4개(`maxCourts`, 여러 코트는 같은 시간). 배드민턴은 매일 00:00~24:00 이고 **자정을 넘겨 다음 날 새벽까지 한 신청으로** 담을 수 있음(2026-10-19 — 그 날 마지막 칸이 24:00 에 끝나고 다음 날이 00:00 으로 시작하는 공간만, `joins`): 22:00 을 누르고 달력에서 다음 날을 눌러 같은 코트의 02:00 칸을 누르면 22:00~다음 날 03:00 (앞날로도 — 다음 날 칸을 먼저 담고 앞날 칸을 눌러도 이어짐). 시간 줄 = 그 날 칸 + 다음 날 칸(`lineOf`, sel.s~e 는 그 줄 index), 담은 시간이 24:00 에 끝나면 표 위 '다음 날 보기 →', 바로 다음 날을 보고 있으면 '같은 코트의 이 날 칸을 누르면 자정 넘어 이어서 담겨요', 요약·확인창은 '10월 19일(월) ~ 10월 20일(화)' · '22:00~다음 날 03:00 (5시간)'. 신청 items 는 두 날짜 칸 그대로(관리프로그램은 원래 여러 날짜를 받음). 레슨 시간·레슨 뒤 정리 시간(:30 에 끝나면 30분, 정시에 끝나면 1시간)은 관리프로그램이 막힌 칸('—')으로 알려줌(시간표에서 계산 — 홈페이지엔 시각을 적어 두지 않고 따로 표시하지 않음). 빈 칸을 누르면 시작점, 같은 코트의 다른 칸을 누르면 시작~그 칸(앞뒤 방향, 사이에 '—' 가 있으면 안내 후 누른 칸에서 새로 시작). 범위가 있으면 첫 칸 = 그 코트 빼기(마지막 코트면 전부 해제), 가운데 = 거기까지로 줄이기(모든 코트 같이), 끝 칸 = 그대로, 선택된 코트 열의 범위 밖 = 새로 시작. 선택 안 된 코트 열의 아무 칸 = 그 코트를 같은 시간으로 추가(범위 중 '—' 가 있으면 'COURT 2는 10:00~18:00 중 예약된 시간이 있어요' 안내만). 코트를 모두(4면) 고르면 '전체대관'(`wholeLabel`). 다른 날짜 칸을 누르면 담은 시간이 지워지고 그 날에서 새로 시작(날짜만 바꿔 보는 건 그대로). 코트 × 시간이 `maxItems`(96 = 4코트 × 24시간)를 넘으면 바꾸지 않음.

  - 결제를 켜고 끄는 건 관리프로그램 Railway 환경변수(`NICEPAY_CLIENT_KEY`·`NICEPAY_SECRET_KEY`·`NICEPAY_MODE`)뿐 — 키가 없으면 지금처럼 신청만 저장(안내 없음). **샌드박스(`NICEPAY_MODE=sandbox`)에서는 주소에 `?paytest=1` 이 있을 때만 결제창**(예: `badminton.html?paytest=1#rental` — 대관·레슨 탭을 오가도 유지, 결과 화면에도 붙어 돌아옴), 일반 손님은 지금처럼 신청만 저장. 샌드박스 결제는 돈이 오가지 않아 관리프로그램이 **신청을 확정하지 않는다**(확인 전 그대로·결제 기록·매출·손님 문자 없음 — 누구나 `?paytest=1` 을 붙일 수 있어서). 운영(`live`)은 모두 결제창이고 결제하면 바로 확정. 키 종류가 모드와 다르면(운영 모드인데 샌드박스 키 등) 관리프로그램이 결제 흐름을 끈다. 시크릿 키·금액 계산은 홈페이지에 없음.
  - **수강신청 카드 결제**(2026-10-16, `apply.js` '온라인 결제' 구역 · 규격은 관리프로그램 `docs/site-api.md` 7~8절): `badminton-apply.html` 의 [신청하고 결제하기] → api `apply`(신청서 저장 — 예전 그대로) → 확인 화면에서 api `pay_options`(고를 것·금액을 관리프로그램이 정함 — 이번 달 남은 수업 / 다음 달, 시간을 '상관없음'으로 골랐으면 시간별로) → 고르고 [N원 결제하기] → `pay_prepare`(kind apply + option) → 나이스페이 결제창(`apply-config.js` `paySdk`·`payMethod`). 결과는 `badminton-apply.html?pay=ok|fail&no=신청번호(&msg=)(&paytest=1)` → '결제가 완료됐어요 — 등록이 끝났어요'(샌드박스면 '테스트 결제 — 등록 안 됨') / '결제가 완료되지 않았어요'(같은 브라우저면 sessionStorage `apPay` 로 대기 주문을 닫고 바로 다시 고르게). 결제창 닫기·오류는 api `pay_cancel`. 결제가 꺼져 있으면(관리프로그램 > 설정 '수강 온라인 결제' — 대관과 달리 운영 모드여도 이 스위치를 켜야 모두에게, 켜기 전엔 `?paytest=1` 시험 주소에서만: 운영 모드면 진짜 결제·진짜 등록) 확인 화면은 '확인 후 담당자가 연락' 그대로. 결제가 되면 관리프로그램이 회원·등록을 만들고 입금완료·안내 문자까지 처리한다.
- **결제 전 환불 규정 · 결제 확인창 · 결제 완료 화면**(2026-10-18, `assets/pay-ui.js` — 수강신청 `apply.js` · 대관 `booking.js` 공용, 모양은 `style.css` 끝 `.pt`·`.pc-dlg`·`.pd`): 결제 전에 관리프로그램 > 안내문의 환불 규정(수강 `refund_class` / 대관 `refund_rental` — `GET /api/site?action=policy&key=`, 관리프로그램 `docs/site-api.md` 3-1절)을 보여 주고 **체크해야 [결제하기]가 켜짐**(글을 못 불러오면 [다시 불러오기] — 결제 불가) → 확인창(수강: 종목·수강·금액·이름·연락처 / 대관: 공간·날짜·코트·시간·금액·이름·연락처 — 취소하면 아무것도 안 보냄, 대관은 칸도 안 잡음) → 결제창(`pay_prepare` 에 `agreeRefund: true` — 관리프로그램이 동의 기록) → 돌아오면 완료 화면(무엇을·얼마에·신청번호 + 다음 할 일: 수강은 '입력한 번호로 결제 확인 문자, 첫 등록이면 앱 로그인 링크 → 앱에서 수업일·출석·재등록 확인', 대관은 확정 문자·취소는 전화). '무엇을·얼마에'는 결제창으로 넘어갈 때 sessionStorage(`apPay`·`bkPay`)에 남긴 것 — 다른 브라우저로 돌아오면 신청번호만. 수강신청 결제 오류는 오류 코드별 문구(`apply.js` `PAY_ERR`), 마감된 옵션은 흐리게 + 아래 글(`sub` — '… · 마감').
