- 대관 예약: `assets/booking.js` + `assets/booking-config.js` + `assets/booking.css` (배드민턴·요가 페이지 `#rental`, 새 화면 클래스는 `.bk2-*` — 달력·폼·머리는 `style.css` 의 `.bk-*` 그대로)
  - 화면: 01 월 달력(날짜, 담은 시간이 있는 날엔 점) → 02 시간 × 코트 표(세로 = 그 날 시간 칸, 가로 = `COURT 1·2·3`, 요가는 '요가센터' 한 열 · 칸 = '선택' / '—'(예약됨 · 레슨 시간 · 레슨 뒤 셔틀 정리 시간 · 지난 시간)) → 아래 고정 요약 바(`10월 16일(금) · COURT 1·2 · 10:00~18:00 (8시간) · 844,800원` + [예약 확인 →]) → 03 신청 폼(위에 선택 요약). 표는 정해진 높이(PC 520px · 휴대폰 55vh) 상자 안에서만 스크롤되고 머리줄·시간 열이 붙어 있으며, 처음·날짜를 바꿀 때 상자 안을 오늘이면 지금 시각, 아니면 첫 빈 칸 근처로 맞춘다(페이지 스크롤은 그대로).
  - 한 신청 = 날짜 하나 + 이어진 시간 범위 하나 + 코트 1~3개(여러 코트는 같은 시간). 배드민턴은 매일 00:00~24:00 — 자정을 넘기는 대관은 날짜별로 따로 신청(23:00~24:00 한 건 + 다음 날 00:00~ 한 건). 레슨 시간·레슨 뒤 정리 시간(:30 에 끝나면 30분, 정시에 끝나면 1시간)은 관리프로그램이 막힌 칸으로 알려줌(시간표에서 계산 — 홈페이지엔 시각을 적어 두지 않음). 빈 칸을 누르면 시작점, 같은 코트의 다른 칸을 누르면 시작~그 칸(앞뒤 방향, 요가 10분 쉬는 시간도 이어진 칸 · 사이에 '—' 가 있으면 안내 후 누른 칸에서 새로 시작). 범위가 있으면 첫 칸 = 그 코트 빼기(마지막 코트면 전부 해제), 가운데 = 거기까지로 줄이기(모든 코트 같이), 끝 칸 = 그대로, 선택된 코트 열의 범위 밖 = 새로 시작. 선택 안 된 코트 열의 아무 칸 = 그 코트를 같은 시간으로 추가(범위 중 '—' 가 있으면 'COURT 2는 10:00~18:00 중 예약된 시간이 있어요' 안내만). 코트를 모두 고르면 '전체대관'(`wholeLabel`). 다른 날짜 칸을 누르면 담은 시간이 지워지고 그 날에서 새로 시작(날짜만 바꿔 보는 건 그대로). 코트 × 시간이 `maxItems`(72)를 넘으면 바꾸지 않음.
  - 신청은 1코트 1시간 칸(선택 코트 × 범위 칸, court 0부터) 단위로 관리프로그램 `/api/site` 에 보냄. 그 사이 예약이 들어와 `conflict` 면 선택을 지우고 표를 새로 불러옴. `api` 가 비면 문자 접수(새 요약 한 줄). 칸은 버튼(aria-label · aria-pressed, 화살표 키로 이동), 결과 안내는 `#bkLive` 한 곳.
  - **온라인 결제(나이스페이)** — `booking.js` '온라인 결제' 구역, 규격은 관리프로그램 `docs/site-api.md` 4~6절. [결제하기] → api `book`(그 시간이 잡힘) → api `pay_prepare`(결제 흐름이 켜졌는지 · 금액 · 주문번호를 관리프로그램이 정함) → 켜져 있으면 그때 나이스페이 JS SDK(`booking-config.js` `paySdk`)를 불러와 결제창(`AUTHNICE.requestPay`, 결제수단 `payMethod`). 결제 결과는 나이스페이 → 관리프로그램이 받아 승인하고 `badminton.html`/`yoga.html?pay=ok|fail&no=신청번호(&msg=)#rental` 로 돌려보냄 → 대관 구역 맨 위 안내(`#bkResult` — '결제 완료 · 예약 확정 — 신청번호 TS…' / 테스트(샌드박스) 결제면 '테스트 결제 완료 — 예약은 확정되지 않았어요(확인 전)' / '결제가 완료되지 않았어요 — 시간을 다시 골라주세요' / '결제 결과를 확인하고 있어요', `msg` 는 관리프로그램 문구와 같을 때만 보임), 주소에서 `pay`·`no`·`msg` 는 지움. 결과 없이 끝난 결제는 api `pay_cancel` 로 잡아 둔 칸을 바로 푼다 — 두 경우로 나뉨: ① 같은 화면이 그대로 있거나 되살아남(결제창 닫기·오류·결제창을 못 엶·결제 대기 15분 초과·휴대폰 결제 화면에서 뒤로 와 bfcache 로 되살아남) → 폼 아래 안내, 고른 시간·입력은 그대로라 바로 다시 결제하거나 시간을 바꿀 수 있음 ② 화면을 새로 엶(휴대폰 결제 화면에서 뒤로 와 새로 열림·`?pay=fail` 결과 화면) → 결제창으로 넘어갈 때 남긴 sessionStorage `bkPay` 기록으로 칸을 풀고 대관 맨 위 안내, 새 화면이라 시간은 다시 고름(`?pay=fail` 이어도 관리프로그램이 주문을 닫지 않은 경우가 있어서 — 인증 결과 서명 불일치·결과 요청이 너무 많음 등). [결제하기] 때 결제창을 열 수 없는 신청이면(`pay_prepare` 오류) 상황대로 안내: 이미 결제됨 → 결제 완료, 승인 중 → 결과 확인 중, 결제 대기 시간이 지남 → 칸을 풀고 '결제 시간이 지났어요 — 다시 결제하거나 시간을 다시 골라주세요', 이미 처리 중인 신청 → 확인 후 연락, 연결 실패 → '신청은 접수됐으니 확인 후 연락'.
  - 결제를 켜고 끄는 건 관리프로그램 Railway 환경변수(`NICEPAY_CLIENT_KEY`·`NICEPAY_SECRET_KEY`·`NICEPAY_MODE`)뿐 — 키가 없으면 지금처럼 신청만 저장(안내 없음). **샌드박스(`NICEPAY_MODE=sandbox`)에서는 주소에 `?paytest=1` 이 있을 때만 결제창**(예: `badminton.html?paytest=1#rental` — 대관·레슨 탭을 오가도 유지, 결과 화면에도 붙어 돌아옴), 일반 손님은 지금처럼 신청만 저장. 샌드박스 결제는 돈이 오가지 않아 관리프로그램이 **신청을 확정하지 않는다**(확인 전 그대로·결제 기록·매출·손님 문자 없음 — 누구나 `?paytest=1` 을 붙일 수 있어서). 운영(`live`)은 모두 결제창이고 결제하면 바로 확정. 키 종류가 모드와 다르면(운영 모드인데 샌드박스 키 등) 관리프로그램이 결제 흐름을 끈다. 시크릿 키·금액 계산은 홈페이지에 없음.
